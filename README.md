# MoonMiles — Find your somewhere

A travel discovery and planning website by **Ankur Patil**. MoonMiles combines an immersive destination-led landing page with destination guides, trip search, an AI itinerary planner, and a conversational travel assistant.

Built with Next.js App Router, React, TypeScript, Tailwind CSS, Radix UI, and Framer Motion.

## The experience

- **Cinematic landing page:** Bali, Santorini, and Maldives photography, circular scene selectors, a pause/play control, and a floating trip-search panel.
- **Scroll storytelling:** the hero image scales and moves at a different speed from its headline; the headline gently fades as it leaves view. A desktop three-chapter scene transitions from coast to Bali to Santorini as the visitor scrolls.
- **Destination discovery:** filter the homepage by islands, city breaks, or culture, then open a detailed destination guide. The full destination directory also supports searching and filtering.
- **Trip search:** choose a destination, optional check-in and check-out dates, traveler count, and currency. Invalid date ranges are rejected before navigation.
- **Search results:** sample transport and accommodation suggestions, outbound booking links, and AI destination insights. USD, EUR, INR, GBP, and AED selections carry through from search.
- **AI itinerary planner:** destination, duration, interests, and special requests feed a day-by-day itinerary generated by Google Gemini.
- **Travel assistant:** a floating chat interface backed by a server-side AI route.
- **Accounts and dashboard:** the existing demo registration, login, logout, profile, and sample trip dashboard remain available.
- **About:** a dedicated founder page featuring Ankur Patil.
- **Contact:** the existing contact details, contact form interface, and submission feedback are retained.

## Project status and boundaries

This is a travel website demonstration, not a production booking or authentication service.

- Account records, including demo passwords, are stored in browser `localStorage`. Use made-up credentials only. Replace this flow with server-side authentication before accepting real users.
- The dashboard uses sample trip data. There is no booking database or persistent itinerary-saving backend.
- The contact form simulates submission; it does not send email. Contact details are demonstration content.
- Search prices, currency conversions, ratings, and destination budgets are illustrative data, not live fares, rates, or availability.
- AI output is generated guidance, not verified current weather, entry requirements, or live travel alerts.
- Final bookings happen on external provider websites. MoonMiles does not collect payments.
- The active design is the light, ivory-and-olive theme. A dark-mode library is installed, but a complete theme-switching experience is not implemented.

## Requirements

- Node.js 20.9 or newer, with a supported LTS version recommended.
- npm; this repository uses `package-lock.json` as its dependency lockfile.
- A Google Generative AI API key for the three AI endpoints.
- Network access for dependency installation, the Inter font during Next.js builds, and AI requests.

The browsing interface works without an AI key; AI generation requires a valid key and available provider quota.

## Local setup

```bash
git clone https://github.com/ank-urrr/MoonMiles-Final.git
cd MoonMiles-Final
npm ci
```

Create `.env.local` at the repository root:

```dotenv
GOOGLE_GENERATIVE_AI_API_KEY=your_google_ai_api_key
```

Do not put this key in a `NEXT_PUBLIC_` variable or commit it. Files matching `.env*` are ignored by Git. The key is read by the Google AI provider on the server, not by browser components.

Start the development server:

```bash
npm run dev
```

Open [localhost:3000](http://localhost:3000).

To choose a different port:

```bash
npm run dev -- --port 3001
```

## Routes

- `/` — landing page, destination filters, trip search, and scroll story.
- `/destinations` — searchable destination directory.
- `/destinations/[id]` — destination detail pages. Supported slugs include `bali`, `santorini`, `maldives`, `tokyo`, `paris`, `london`, `dubai`, and `new-york`.
- `/search-results` — trip options derived from URL search parameters.
- `/itinerary-planner` — AI itinerary generation.
- `/about` — the story and founder of MoonMiles.
- `/contact` — contact UI and demonstration form.
- `/signup`, `/login` — browser-local demonstration accounts.
- `/dashboard` — account view and sample trips.

Search parameters are `destination`, `checkIn`, `checkOut`, `travelers`, and `currency`. Dates use `YYYY-MM-DD`. Leave both dates unset for a flexible-date search; choosing one date requires the other, and check-out must be later than check-in.

## AI endpoints

All three routes use the Vercel AI SDK, `@ai-sdk/google`, and `gemini-2.5-flash`.

### `POST /api/chat`

Request:

```json
{
  "messages": [
    { "role": "user", "content": "What should I see in Bali?" }
  ]
}
```

Response: `{ "response": "..." }`.

### `POST /api/itinerary`

Request:

```json
{
  "destination": "Bali, Indonesia",
  "duration": "4-6 days",
  "preferences": ["Nature & outdoors", "Culture & history"],
  "requirements": "A relaxed pace with time for local food"
}
```

Response: `{ "itinerary": "..." }`.

### `POST /api/insights`

Request:

```json
{ "destination": "Tokyo, Japan", "currency": "USD" }
```

Response: `{ "insights": "..." }`.

These endpoints do not implement production authentication, rate limiting, or persistent conversation storage. Add those controls before operating a public AI service with real traffic.

## Motion and performance

Motion is deliberately tied to browser timing rather than a fixed 30/60 FPS loop:

- CSS transforms and opacity handle scene crossfades, subtle image drift, hover effects, and entrance reveals.
- Framer Motion `useScroll` and `useTransform` connect scroll position directly to transforms and opacity without React state updates on each frame.
- The optional canvas background uses `requestAnimationFrame` timestamps and pixels-per-second movement. It cancels its scheduled frame on unmount and pauses while the document is hidden.
- The hero's eight-second timer changes slides only; it does not set the frame rate. Automatic cycling stops when the hero is offscreen, the page is hidden, a scene control is being used, or reduced motion is requested. Manual scene selection pauses automatic cycling.
- The three-chapter story uses native document scrolling and CSS sticky positioning. There is no scroll hijacking, wheel interception, or artificial smooth-scroll engine.
- On narrow screens and short viewports, the story becomes a simple static scene to keep touch navigation direct.
- `prefers-reduced-motion` disables decorative movement, automatic scene cycling, smooth anchor scrolling, and the long pinned story.
- Local images have explicit card dimensions and below-the-fold images load lazily. The first hero image has high fetch priority.

There is no application-imposed FPS cap. Actual refresh cadence depends on the monitor, browser, OS power settings, GPU, and workload. A web page cannot force a display to run at a particular refresh rate, and a 120/144/240 Hz claim requires testing on that hardware.

## Editing the design

- Update hero destinations in the `scenes` array in `components/hero-section.tsx`.
- Edit homepage destination cards and their categories in `components/destinations-section.tsx`.
- Change the scroll story's three images and chapter labels in `components/journey-section.tsx`.
- Update colors and responsive rules in `app/moonmiles.css`. The main palette is warm ivory `#f7f6f0`, deep olive `#34452e`, and muted sage accents.
- Update the founder text in `app/about/page.tsx`; the portrait is `public/Ankur.jpg`.
- Keep content and image changes consistent with destination records in both the directory and detail routes.
- Keep the existing API routes and account provider connected when changing presentation components.

## Verification checklist

1. Run `npm run typecheck` and `npm run build`.
2. Check the landing page at desktop, tablet, and phone widths; confirm there is no horizontal overflow.
3. Select all hero scenes, pause/resume cycling, and scroll through the hero and desktop story.
4. Enable the operating system's reduced-motion preference and verify that content stays visible without decorative movement.
5. Filter destinations and open at least one detail page.
6. Search with flexible dates and with a valid future date range. Check that invalid or incomplete dates cannot submit.
7. Confirm the selected currency, destination, and traveler count reach search results.
8. Open and close the mobile menu using keyboard/touch; verify Escape closes it and focus returns to the trigger.
9. Open the chat panel on a narrow screen and confirm its input and send button fit.
10. With a valid provider key, verify the planner, chat, and destination-insight requests. Check provider errors without exposing secrets.
11. Check that About includes only Ankur's founder profile.

## Deployment

Deploy to a host that supports Next.js server routes, such as Vercel or a Node.js server. A static-only host cannot execute the AI endpoints.

1. Connect this repository and select the desired Git branch.
2. Install dependencies with `npm ci`.
3. Add `GOOGLE_GENERATIVE_AI_API_KEY` in the host's server-side environment settings.
4. Build with `npm run build` and serve with the host's Next.js integration or `npm run start`.
5. Verify the published URL and AI endpoints after deployment.

Pushing source to GitHub does not by itself establish that a deployment has succeeded. A connected hosting provider may build automatically; check its deployment status separately.

## Troubleshooting

- **AI responses fail:** check the server-side key, provider quota, model access, and outbound network availability. Restart the dev server after changing `.env.local`.
- **A build cannot fetch Inter:** ensure the build environment can reach Google Fonts, or replace the font with a locally bundled licensed font.
- **Port 3000 is busy:** use `npm run dev -- --port 3001`. Avoid running two dev instances against the same `.next/dev` directory.
- **A demo account disappears:** demo accounts are local to the browser and origin. Clearing storage or changing ports removes access to that local state.
- **Contact messages do not arrive:** the current form is a UI demonstration; connect a mail service before using it for real enquiries.
- **Animations are static:** check the reduced-motion setting, page visibility, selected slide's pause state, and viewport size.
